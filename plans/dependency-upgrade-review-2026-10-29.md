# Dependency upgrade review — 2026-10-29

Upgrade the production framework and authentication stack first, followed by database, email, telemetry, editor, and test dependencies. Keep unrelated major migrations separate.

This is an assessment, not an implemented upgrade. Versions below are resolved lockfile versions and npm registry targets observed during this review; compatibility and a clean post-upgrade audit still need verification.

## Security findings that matter here

**Node.js runtime: mandatory production verification.** The October 21 security release provides Node **24.22.1** with fixes for CVE-2026-111497 (Brotli decoder memory corruption / possible RCE), CVE-2026-105482 (DNS NUL handling), CVE-2026-105483, CVE-2026-106069 and CVE-2026-106072 (TLS identity checks), plus HTTP keep-alive and other fixes. Brotli exploitation requires attacker-controlled compressed bytes to reach decompression; a reachable path has not been demonstrated here. Alpine does not justify skipping this runtime patch. [Node security announcement](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases), [24.22.1 release](https://nodejs.org/en/blog/release/v24.22.1).

Both production Dockerfiles currently use `FROM node:24-alpine AS base`, and their final runners inherit that base. This identifies the major version only. Cached builds and already-running containers can retain an earlier vulnerable patch even after the upstream tag changes. Neither `package.json` engines nor npm audit verifies the Node executable inside a deployed container.

Make these release acceptance requirements:

1. Re-check the official Node release/security feed when implementing. Stay on supported Node 24 and select the latest patched 24.x release, with **24.22.1 as the minimum for the October advisories**. Resolve the official Alpine image for the production architecture and pin its version and verified digest in both Dockerfiles; do not invent or copy a digest from a different platform.
2. Refresh the base image during the build (`pull: true` in both build-push-action steps, or `docker build --pull`). Build both complete production images and scan those final images for Node, Alpine, OpenSSL, and native-library findings. A base-image scan alone is insufficient.
3. Before deployment, execute `node -p 'JSON.stringify(process.versions)'` in each built final image using `--entrypoint node`, avoiding the normal application startup/migration script. Fail CI if the Node patch does not meet the current approved baseline. Record the image digest and runtime output.
4. Deploy both rebuilt images and replace every old replica. Inspect `node -p 'JSON.stringify(process.versions)'` inside **each running production container**, and verify that its image identity matches the scanned release. This post-deployment check is required before calling production patched.
5. Automate version/digest update proposals and recurring scans. Pinning establishes reproducibility but requires ongoing updates; this baseline is dated, not a permanent claim of freedom from vulnerabilities.

The deployed runtime remains **unverified** in this assessment: no production host/container access was used. This requirement is an addition to the upgrade chore, not a claim that a production rollout has occurred.

**Next.js: high-confidence public exposure.** Both apps use App Router and Server Actions. CVE-2026-64641 and CVE-2026-94482 concern Server Action denial of service; the latter is fixed in 16.4.1. This repo meets the feature prerequisites. Upgrade to 16.4.3 rather than stopping at an earlier security patch. [Server Actions advisory](https://github.com/vercel/next.js/security/advisories/GHSA-p3m5-59mp-jv5r).

The admin has a `proxy.ts` redirect gate, so CVE-2026-45109 and CVE-2026-44574 proxy bypasses also matter. `requireAuth()` performs real session/role validation and limits impact where called; do not rely on cookie presence in the proxy for authorization. [Proxy bypass advisory](https://github.com/advisories/GHSA-26hh-7cqf-hhc6).

Image optimization is used by shared cards and the public site. Include CVE-2026-27980 (disk cache exhaustion), CVE-2026-44577 (image DoS), and Sharp's native decoder fixes. CVE-2026-96889 concerns SVG processing; the published RCE condition is glibc Linux, whereas these Dockerfiles use Alpine/musl. The AVIF advisory also involves runtime-specific native-library conditions. Do not label these confirmed RCE on the configured containers, but patch both Next and Sharp. [SVG advisory](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw), [Sharp AVIF advisory](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c).

Several other Next findings have absent prerequisites: no Windows production image, no `use cache` functions found, no configured rewrites, and no Pages Router. In particular, CVE-2026-94543's Pages Router cache poisoning is not established here just because public App Router pages use ISR. Image SSRF exposure is reduced by the public app's specific S3 hostname allowlist; the admin has no remote image allowlist. [Cache poisoning scope](https://github.com/vercel/next.js/security/advisories/GHSA-4jqv-mc3x-m676).

**Better Auth: upgrade and close open registration.** The app enables email/password and emailOTP. GHSA-qq9h-g4jm-xgf3 allows a planted password to survive the email owner's OTP login when open registration is enabled; fixed in 1.6.22. The observed configuration meets the relevant prerequisites. OAuth/OIDC/MCP/SSO findings, including CVE-2026-114607 and CVE-2026-53512, should not be described as active account takeover paths here: those plugins/providers are not configured. The admin plugin's stale-session cleanup advisory is relevant. [OTP advisory](https://github.com/better-auth/better-auth/security/advisories/GHSA-qq9h-g4jm-xgf3).

Separately, source review found a more direct authorization problem, independent of CVEs:

- `apps/admin/src/lib/auth.ts` enables password signup without `disableSignUp` or an invitation hook, and sets `defaultRole: "admin"`.
- `apps/admin/src/app/api/auth/[...all]/route.ts` exports the generic auth handler; `proxy.ts` allows `/api/auth` publicly.
- Invitation validation exists only in `apps/admin/src/app/accept-invitation/actions.ts`.
- Installed Better Auth source confirms the signup endpoint accepts registrations unless disabled and the admin plugin assigns the configured default role.

Inference: a direct signup request can bypass the invitation UI and create an admin account if no external control blocks the endpoint. This was not exercised against a database. Restrict account creation at the server boundary and grant admin only through the authorized invitation/provisioning flow. Cover both password and OTP account creation. Simply disabling signup may also break the existing invitation action, which calls `auth.api.signUpEmail`; redesign and test those together.

Upgrade directly to the selected patched 1.7 release, reviewing adapter/API changes. Do not add the transient `issuer` schema migration from 1.7.0–1.7.2: it was reverted in 1.7.3. Compare the actual schema and test existing accounts. [Maintainer migration correction](https://better-auth.com/blog/1-7-account-schema).

**Database: patch with relatively low migration cost.** CVE-2026-39356 affects Drizzle ≤0.45.1 and permits injection through attacker-controlled SQL identifiers/aliases. Searches found static schema-based queries and no `sql.identifier`, `sql.raw`, or `.as()` calls in app/package TypeScript, so no reachable injection path was identified. Patch all ORM references anyway. MySQL2's auth downgrade requires a malicious/intercepted database connection; compression DoS requires compression, which this client does not configure. The database client also does not explicitly configure TLS. [Drizzle advisory](https://github.com/drizzle-team/drizzle-orm/security/advisories/GHSA-gpj5-g38j-94v9), [MySQL auth downgrade](https://github.com/advisories/GHSA-3f6p-5ww8-9rcr).

**Email: update the entire chain.** Production uses `nodemailer-mailgun-transport@2.1.5 → mailgun.js@8.2.2 → axios@1.13.5`, plus `form-data@4.0.5`. Updating Nodemailer alone leaves those dependencies. Refresh Axios to ≥1.20.0 and form-data to ≥4.0.6 through compatible resolutions, or replace the old transport with a maintained Mailgun integration. The snapshot reports no newer transport release. SMTP/OAuth2-specific Nodemailer CVEs are less applicable to the configured Mailgun HTTP path; address parsing still deserves testing. Arbitrary-file-read CVE-2026-82659 requires attacker influence over message `raw` options, which was not established. [Raw-content advisory](https://github.com/advisories/GHSA-p6gq-j5cr-w38f), [multipart advisory](https://github.com/advisories/GHSA-hmw2-7cc7-3qxx).

**AWS and telemetry: production dependencies, conditional exploitability.** S3 pulls `fast-xml-parser@5.3.4`, including CVE-2026-25896 and CVE-2026-26278; later fixes require at least 5.7.0 across the snapshot's findings. The app talks to AWS S3 rather than an attacker-configured XML endpoint, so uploaded object bytes alone do not establish XML parser exposure. PostHog pulls DOMPurify 3.3.1 and protobufjs 7.5.4. CVE-2026-41242 involves protobuf code generation; no untrusted schema-loading path was identified. Refresh parent packages and verify transitives, including protobufjs ≥7.6.5. DOMPurify includes a no-patch advisory in this snapshot; document its specific live-DOM prerequisites rather than promising a universally clean audit.

**Editor: genuine browser exposure.** CVE-2026-104847 affects pasting attacker HTML into ProseMirror; admins use this editor, so prioritize the compatible `prosemirror-view` fix. Update markdown-it and linkify-it as a group. The shared public Markdown component uses rehype-sanitize after rehype-raw, which is a useful existing protection. Tiptap's separate `mergeAttributes` advisory needs attacker-controlled attribute objects; investigate custom extensions during the v3 migration. [Paste XSS advisory](https://github.com/advisories/GHSA-c8x8-7fp4-3x9w), [Tiptap advisory](https://github.com/advisories/GHSA-cp6q-959q-f8rh).

**Tests/tooling: upgrade, but do not equate findings with public app exposure.** CVE-2026-47429 concerns Vitest UI/API exposure or Windows UI/browser mode; current scripts use `vitest run` and no exposed API was found. Tinypool RCE findings require prototype-pollution prerequisites. Vite/esbuild development servers, Rollup, ESLint's minimatch, and other build dependencies belong in the tooling chore. ExcelJS is used for browser exports, not untrusted workbook imports or archive extraction in the reviewed code; its archive dependency findings need separate reachability assessment. [Vitest advisory](https://github.com/advisories/GHSA-5xrq-8626-4rwp).
